# Design: Astryx to Shadcn UI Migration Architecture

## Context

See `proposal.md` for motivation. Currently, 33 frontend files import components from `@astryxdesign/core`. Internal styles compile via StyleX, while external layouts compile via Tailwind v4. The goal is to migrate every Astryx component callsite to a local Shadcn UI primitive (`src/components/ui/`), delete the StyleX toolchain, and enforce strict visual invariance.

## Goals / Non-Goals

**Goals:**
- Replace 100% of `@astryxdesign/core` and `@astryxdesign/theme-neutral` imports across all 33 files.
- Install and configure official Shadcn UI primitives (`button`, `card`, `badge`, `separator`, `input`, `checkbox`, `select`, `toggle-group`, `hover-card`, `dialog`, `drawer`, `sonner`).
- Retain exact visual fidelity: colors, fonts (Fredoka/Nunito), border radii, shadows, and canvas geometries.
- Cleanly uninstall `@astryxdesign/core`, `@astryxdesign/theme-neutral`, and `@stylexjs/stylex`.
- Pass all unit tests (90/90 Vitest), linting (`pnpm exec eslint . --max-warnings 0`), and full production SSG prerender (`pnpm run build`).

**Non-Goals:**
- Redesigning UI UX or modifying user workflows.
- Altering the ReactFlow canvas physics, layout graph algorithm (Dagre), or edge validation.
- Modifying backend schemas, endpoints, or block execution engines.

## Decisions

### Decision 1: Component Architecture & File Organization
All Shadcn UI primitives reside in `src/components/ui/` (`button.tsx`, `card.tsx`, `input.tsx`, `dialog.tsx`, etc.), generated by the official Shadcn CLI with Tailwind v4 styling and the `@/lib/utils` `cn` helper.

```
+--------------------------------------------------------------------------+
|                       New Component Architecture                         |
+--------------------------------------------------------------------------+
|                                                                          |
|   App Pages & Canvas Components                                          |
|   (BlockNode, SuperBlockNode, EditorHeader, FlowPalette, Login, etc.)     |
|         |                                                                |
|         v                                                                |
|   src/components/ui/  <-- 100% local, editable Shadcn components         |
|   (button, card, badge, input, select, checkbox, drawer, dialog)        |
|         |                                                                |
|         v                                                                |
|   Radix Primitives + Vaul + Tailwind CSS v4                              |
|         |                                                                |
|         v                                                                |
|   Single LightningCSS / Tailwind v4 build pass                           |
|                                                                          |
+--------------------------------------------------------------------------+
```

*Rationale*: Unlike Astryx which hid components inside `node_modules/@astryxdesign/core/dist`, Shadcn components live directly in the repository, making them transparent, debuggable, and zero-conflict with Tailwind utilities.

### Decision 2: Direct Mapping of Layout & Typography
Instead of creating heavy wrappers:
- `HStack` / `VStack` are replaced directly by `<div className="flex items-center gap-...">` or `<div className="flex flex-col gap-...">`.
- Astryx `<Text>` and `<Heading>` are replaced by semantic HTML elements (`<p>`, `<span>`, `<h1>`..`<h3>`) styled with `text-text`, `text-text-muted`, and `font-heading`.
- Astryx `<Icon icon={Save} size="sm" />` is replaced by direct Lucide components (`<Save className="size-4" />`).

*Rationale*: This eliminates unnecessary wrapper layers and reduces React component tree depth.

### Decision 3: BottomSheet Replacement with Vaul Drawer
Astryx's `BottomSheet` is replaced by Shadcn's `Drawer` primitive (backed by `vaul`).
- Preserves smooth touch gestures, drag-to-dismiss handle, and backdrop blur.
- Used in `FlowCanvas.tsx` for mobile drawer and SuperBlock detail inspection.

### Decision 4: File Input Modernization
Astryx's `FileInput` is replaced by standard Shadcn `<Input type="file" />` with custom file card UI already existing in `BlockSegments.tsx`.

### Decision 5: Centralized Theming & WCAG 2.1 AA Color System
All styling across the application MUST be driven by centralized CSS custom properties in `src/index.css`. Hardcoded color literals (`#...`, `rgba(...)`) inside components are strictly prohibited.

- **Primary Accent**: `#D97757` (warm terracotta), providing robust contrast against both dark surfaces (5.7:1) and light backgrounds.

### Decision 6: ThemeToggle Component with Lucide Sun & Moon
An accessible toggle button component (`src/components/ui/theme-toggle.tsx`) will be installed in the top navigation bar (`HomeNav.tsx`) and the canvas editor header (`EditorHeader.tsx`).
- Uses Lucide `Sun` (displayed when dark mode is active to toggle to light) and `Moon` (displayed when light mode is active to toggle to dark).
- Toggles `document.documentElement` attributes (`class="dark"` and `data-theme="dark|light"`).
- Persists the user preference in `localStorage` under `mlblock-theme` (`light` | `dark` | `system`).

### Decision 7: Phased Implementation Sequence
1. **Phase 1 — Core UI Primitives & Centralized Tokens**: Install Shadcn `card`, `badge`, `separator`, `input`, `checkbox`, `select`, `toggle-group`, `hover-card`, `dialog`, `drawer`, `sonner`. Define full Light & Dark tokens with `#D97757` in `index.css`. Implement `ThemeToggle` with Lucide `Sun`/`Moon`.
2. **Phase 2 — Marketing & Auth Pages**: Migrate `SiteLayout`, `HomeNav`, `HomeFooter`, `HeroSection`, `FeaturesSection`, `LoginPage`, `RegisterPage`, `AboutPage`, `HowItWorksPage`, `ProjectsPage`. Integrate `ThemeToggle`.
3. **Phase 3 — Modals & Overlays**: Migrate `ExportModal`, `TemplateModal`, `SampleDataModal`, `ConverterDialog`, `UnsavedChangesDialog`, `EditorUnavailableModal`, `Toast`.
4. **Phase 4 — Editor & Canvas**: Migrate `EditorHeader`, `FlowPalette`, `BlockSegments`, `BlockNode`, `SuperBlockNode`, `SuperBlockBodies`, `JournalPanel`, `ResultsPanel`, `FlowCanvas`. Eliminate all hardcoded color literals in favor of theme classes.
5. **Phase 5 — Cleanup, Contrast Audit & Verification**: Remove `@astryxdesign/core`, `@astryxdesign/theme-neutral`, `@stylexjs/stylex`, remove `@stylex` from `index.css`, verify WCAG AA contrast, run test suite and production build.
## Risks / Trade-offs

- **Risk: Canvas Block Dimensions & Port Alignment**: ReactFlow handle anchors rely on precise bounding boxes. If `Card` padding drifts, edge connections may misalign.  
  *Mitigation*: Retain exact padding (`p-3`), port spacing, and CSS dimensions on `BlockNode` and `SuperBlockNode`.
- **Risk: ESLint `@shadcn/lint` noise on generated files**:  
  *Mitigation*: We already scoped ESLint to allow generated UI primitives in `src/components/ui/` and standard sizing styles.
- **Risk: Dark theme consistency**:  
  *Mitigation*: Tokens in `src/index.css` under `.dark, [data-theme="dark"]` are explicitly linked to MLBlock's dark color palette (`#171311`, `#1f1916`, `#221c19`, `#B8552E`).

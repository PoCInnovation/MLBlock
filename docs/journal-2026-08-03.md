## 10. Type checking & conversions — feu tricolore (`type-checking-conversions`)

Le plus gros morceau de la session : vérification de types **visible dans l'UI** sur les deux espaces de travail, avec conversion automatique quand nécessaire.

### Le constat

Les types existaient déjà dans les annotations des 64 blocs (`torch.Tensor`, `pd.DataFrame`…), mais tout le pipeline les ignorait :

- `inputs` **jamais dérivés** (`[]` pour tous les blocs) — le validator `validate_dtype_compatibility` existait mais était **code mort** (aucune instanciation de `PipelineDef`, et il aurait crashé : `StopIteration`)
- Le frontend **jetait** `inputs`/`outputs` dans `fetchCatalog` (le schéma zod les parse, le mapping les droppe)
- Le mode linéaire envoyait `edges: []` → chaque bloc tournait isolément, aucun check

### Système de types backend

- **Dérivation des inputs** dans `_inspect_function` : port si nom `in_<chiffres>` ou type data (`pd.DataFrame`, `torch.*`, `Model`, `object`, `tuple[...]`) ; le dtype vient de l'annotation **brute** (`get_type_hints` perd le préfixe module : `torch.Tensor` → `Tensor`). `input(shape)` et `load_csv(path)` n'exposent aucun port.
- **Multi-sorties** : `-> "tuple[A, B]"` → `out_1`/`out_2` (split top-level). `BlockMeta.execute` normalise le tuple en sorties nommées ; `Pipeline.run` résout **par port** (`_value_for`) — `source_port` était ignoré avant.
- **`core/types.py`** (nouveau) : familles de types (tensor, df, model, dict, dataset, module, optim, scalar…) + **classifieur 4 sorties** — identité / sous-type (`object`/`Any` wildcard) → vert ; chemin dans le graphe de conversion → orange ; sinon → rouge. Le graphe est **dérivé du catalogue** (seuls les blocs `transforms` contribuent : `df_to_tensor`, `to_tensor`).
- **Validation réanimée** : `validate_dtype_compatibility` branché sur `/api/validate` **et** `/build` (échec rapide 400 au lieu de l'erreur runtime).

### Convertisseurs

| Bloc | Signature | Rôle |
|---|---|---|
| `df_to_tensor` (**nouveau**) | `pd.DataFrame → torch.Tensor` (float32) | le pont CSV → réseau |
| `to_tensor` (resserré) | `object → numpy.ndarray → torch.Tensor` | fini le wildcard menteur (`ToTensor` crashait sur un DataFrame) |

### Audit complet des blocs : 5 cassés, réparés

Scan AST des 64 blocs (noms lus non définis) — 5 blocs avaient un NameError garanti :

| Bloc | Bug | Fix |
|---|---|---|
| `linear_regression`, `logistic_regression`, `random_forest` | `fit(train_data, train_target)` — `train_target` inexistant | `X = train_data.drop(target_column)`, `y = train_data[target_column]` |
| `evaluate` | `test_target` inexistant + `method` ignoré | réécrit : X sans cible, `mse`/accuracy réels, retour `float` |
| `train_test_split` | corps entier référant des noms inexistants | réécrit via sklearn (`ratio`/`shuffle`/`seed`), retour tuple → **éclaté** `out_1: train`, `out_2: test` |

`random_split` éclaté aussi (`tuple[Dataset, Dataset]`). `pca`/`standard_scaler`/`train_model` restent mono-sortie `dict` (types des valeurs inconnus — v2).

### UI — le feu tricolore

Décisions utilisateur actées : **orange = bouton « Convertir »** qui matérialise le nœud convertisseur ; **rouge = connexion bloquée + toast**.

```
connecter A.out → B.in
   identité / sous-type / même famille   🟢 vert  → edge créé
   convertisseur dispo (df→tensor…)      🟠 orange → toast « Convertir » → insère le bloc au point milieu + recâble
   aucun chemin                          🔴 rouge  → edge non créé + toast d'erreur
```

- **Catalogue enrichi** : `BlockDef` gagne `inputs`/`outputs` (`{name, dtype}`), propagés par `fetchCatalog`
- **`BlockNode` multi-handles** : un handle par port (`train_epoch` : `in_1`..`in_4` ; `train_test_split` : `out_1`/`out_2`), dtype au survol (`title`)
- **Edges colorisés** au rendu : vert `success`, orange `convert` `#F59E0B` **pointillés**, rouge `error`
- **Toast système** (nouveau, store zustand + `components/ui/Toast.tsx`) : `role="alert"`, auto-dismiss 5s, bouton action pour le convert — il n'existait pas
- **Mode simple** : connecteur implicite `out_1(N) → in_1(N+1)` coloré entre blocs (`ChainConnector`) — orange → bouton « Insérer convertisseur (df_to_tensor) » inter-blocs, rouge → badge `✗ incompatible (types)`
- Accessibilité : couleur + symbole (● / ⚡ / ✗) — pas de vert/rouge seul

## 11. Fix clignotement mode avancé — controlled flow (`14d009c`)

**Bug signalé** : les blocks clignotaient une fois posés en mode avancé.

**Diagnostic instrumenté** (drops synthétiques + compteurs) : **boucle de rendu infinie** — jusqu'à 1400 re-renders/s, 287 remounts DOM des nodes en 5s, erreur React `Maximum update depth exceeded` (via `forceStoreRerender` de zustand). La cause : le **double-sync canvas↔store** (push `setFlowNodes` + resync) — zustand notifie de façon synchrone, StrictMode (dev) amplifie la course, et chaque effet écrivait l'état périmé de l'autre dans le même flush. `onNodesChange` ne tirait jamais — la boucle était 100 % entre nos 2 effets.

**Fix** : **une seule source de vérité — pattern « controlled flow » de la doc ReactFlow** :
- Store : `applyFlowNodeChanges`/`applyFlowEdgeChanges` (via `applyNodeChanges`/`applyEdgeChanges`), `addFlowNode`, `addFlowEdges`
- `FlowCanvas` : `nodes={flowNodes}` / `edges={renderEdges}` directement depuis le store ; `onNodesChange`/`onConnect`/`onDrop` écrivent dans le store ; **les 3 effets de sync supprimés**
- Vérifié : 2 drops → 2 nodes stables, churn DOM = 2 (zéro remount), aucune erreur

## 12. Params éditables en mode avancé (`advanced-mode-params`)

Le mode avancé construisait des graphes mais ne pouvait ni régler ni exécuter les hyperparamètres : `BlockNode` les affichait en lecture seule, le run envoyait `params: {}`, `linearToFlow` reconstruisait les valeurs depuis les défauts.

**Découverte majeure en exploration** : **aucune coercion de type dans le backend** — `nn.Linear(in_features="4")` → TypeError. Le run **linéaire** avec valeurs éditées était donc cassé aussi (62/65 blocs ont des params requis).

- **`BlockMeta.coerce_params`** : strings frontend → types déclarés (`int`/`float`/`bool`/`list` via `json.loads`, vide → `None` pour optionnel) avant `execute` — fixe linéaire **et** avancé ; build endpoint : coercion avant l'inférence de forme des racines
- **Node data** : `segs` + `fields` (au lieu de `params` lecture seule) ; `BlockNode` rend `BlockSegments` **éditables** (num → input, sel → select, file → upload)
- **Préservation** : `linearToFlow` propage `b.fields`, `flowToLinear` lit `data.fields` — les valeurs survivent aux bascules
- **Runner avancé** : envoie `data.fields` au lieu de `{}`
- **`fetchCatalog`** : les ports de données (`dataset`) n'apparaissent plus comme champs fantômes
- Vérifié : pytest 18/18, core run conv2d racine avec strings → `Tensor (1, 16, 26, 26)`, navigateur (édition `ratio=0.5` → store à jour, bascules préservées)

## 14. Keep-alive backend + fix déploiement (`backend-keep-alive`, `fef9b4e`)

### Fix déploiement — port scan timeout

Déploiement échoué : `Port scan timeout reached` — le service n'a jamais bindé. Causes empilées : **Python 3.14 par défaut** (jamais testé), **font cache matplotlib construit à l'import** (~30-60 s sur instance 0.1 CPU), torch CUDA 5,5 Go inutile sans GPU.

- `render.yaml` : `pythonVersion: 3.11` (aligné dev local)
- `plot_predictions` : import matplotlib **lazy** (`use("Agg")` dans la fonction) → **import mesuré 1,36 s sans cache** (avant : font cache à l'import)
- `gymnasium` + `stable-baselines3` retirés (blocs rl supprimés, zéro import résiduel) + `uv.lock` régénéré
- **Fix latent** découvert en vérif : `coerce_params` faisait `value == ""` sur un DataFrame → `truth value ambiguous`. Garde `isinstance(value, str)`.

- **Branches** : `ali/dev` fast-forwardée sur main ; `origin/frontend-backend-connection` mergée avec main (conflits résolus en faveur de main — branche juillet 2026 subsumée)

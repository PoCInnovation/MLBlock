**Date:** 2026-09-09

**MLBlock Context:** `backend/mlblock/core/types.py:family_of()` maps `torch.Tensor*`→`tensor`, `torch.nn.*`→`module`, `torch.optim.*`→`optim`, `torch.utils.data.*`→`dataset`, etc., with `classify()` verdict `compatible/convertible/incompatible` and `build_conversion_graph()`. Blocks are `BlockMeta` (`inputs`/`outputs` dtype strings) discovered via `Catalog` scanning `blocks/{category}-{HEX}/*.py`.

| Pattern | Intent (refactoring.guru, 1-sentence) | Fit for MLBlock Type Unification — helps vs hurts (Python/torch) | Risk |
|---|---|---|---|
| **Adapter** | Structural: allows objects with incompatible interfaces to collaborate. — https://refactoring.guru/design-patterns/adapter | **Helps** when legacy blocks emit `numpy.ndarray`/`pd.DataFrame`/`PIL.Image` but pipeline expects `torch.Tensor` — wrap `build_fn` with `TensorAdapter` translating without touching N files; lets `family_of()` stay narrow while conversion at edges. **Hurts** if used *instead of* unifying: cements sprawl, hides shape/dtype mismatches that should be explicit. | Extra indirection; silently fixes `float32/float64` or `cpu/cuda` → latent bugs; proliferation of `*Adapter` classes duplicates logic belonging in `build_conversion_graph`. |
| **Bridge** | Structural: split a large class or set of closely related classes into two separate hierarchies — abstraction and implementation — which can be developed independently. — https://refactoring.guru/design-patterns/bridge | **Helps** to kill combinatorial explosion (`BlueCircle/RedSquare`): split Block abstraction (`Category`) from torch implementation (`tensor`/`module`/`dataset`); adding `bfloat16` doesn't require new block classes. **Hurts** for thin code-gen wrappers where blocks are just `template+spec`; premature doubling of hierarchies. | Drift between hierarchies when `torch.nn` API changes; harder for contributors writing single-file blocks. |
| **Composite** | Structural: compose objects into tree structures and then work with these structures as if they were individual objects. — https://refactoring.guru/design-patterns/composite | **Helps** if pipelines become nested sub-graphs: treat `Pipeline` and `Block` uniformly via `Component` (`execute()`, `inputs/outputs` aggregation), recurse over `tuple[Tensor,Tensor]`. **Hurts** on flat DAG (`core/graph.py`/`pipeline.py`): forces leaves to implement `add()/remove()`, violating ISP. | Overgeneralized interface; `Composite[Tensor]` pretending to be `Tensor` breaks `torch.autograd` shape contracts. |
| **Decorator** | Structural: attach new behaviors to objects by placing these objects inside special wrapper objects that contain the behaviors. — https://refactoring.guru/design-patterns/decorator | **Helps** to layer dtype/device concerns: `NormalizeDecorator`, `CastDecorator`, `DeviceDecorator(cuda)` wrap `BlockMeta.build_fn`; `Catalog` stacks `Device(Normalize(Block))` avoiding `Conv2dCudaFp16Normalized` explosion. **Hurts** when goal is one canonical `Tensor` type; decorators preserve soup and order `Cast→Normalize` ≠ `Normalize→Cast`. | Order-dependence bugs; `isinstance(x, torch.nn.Module)` / `torch.jit` breaks; config UI must serialize stacks. |
| **Facade** | Structural: provide a simplified interface to a library, a framework, or any other complex set of classes. — https://refactoring.guru/design-patterns/facade | **Helps** as primary unification: one `TensorFacade.to_tensor(x:Any)->torch.Tensor` hiding `numpy/PIL/DataFrame` + codec complexity; frontend/`validation.py`/`execution.py` call only `facade.convert(src_family,dst_family)`; swapping `torch`→`mlx` touches one file. **Hurts** if facade becomes god-object swallowing distinctions pipeline needs (`tensor`/`module`/`optim` merged). | Coupled to all 44 blocks; tempts implicit lossy `DataFrame→tensor` dropping columns. |
| **Strategy** | Behavioral: define a family of algorithms, put each into a separate class, and make their objects interchangeable. — https://refactoring.guru/design-patterns/strategy | **Helps** to replace `if dtype.startswith("torch.Tensor")` chains in `family_of`/`classify`; extract `ConversionStrategy` (`TensorStrategy`, `ModuleStrategy`, `WildcardStrategy`) with `execute(src,dst,graph)`; open for new torch types without editing core; Python functional `Callable` alternative avoids class bloat. **Hurts** if 2–3 stable families rarely change — new interfaces bloat with no win. | Selection leaks to caller; YAGNI if rarely changed; client must know which strategy to pick. |
| **Factory Method** | Creational: provide an interface for creating objects in a superclass, but allow subclasses to alter the type of objects that will be created. — https://refactoring.guru/design-patterns/factory-method | **Helps** for `BlockCreator.createOutput(): torch.Tensor` where `VisionBlock`/`SeqBlock` override to return `image` vs `seq` tensors; client `execution.py` works with abstract `Tensor`. Good for `Dataset` vs `Tensor` branching. **Hurts** when creation isn't variation point — recreates `family_of` switch via subclass explosion after normalization to one `Tensor`. | Subclass explosion; static inheritance can't switch at runtime per-params; couples to `BlockRegistry`. |
| **Abstract Factory** | Creational: let you produce families of related objects without specifying their concrete classes. — https://refactoring.guru/design-patterns/abstract-factory | **Helps** when blocks must stay coherent families: `CudaFp16Factory` produces matching `createTensor()`+`createModule()`+`createOptim()` guaranteeing same device/dtype (`ModernFurnitureFactory` analog). **Hurts** for reduction: codifies families instead of erasing them (N types → N factories, not 1). Hurts mixing cpu/cuda legitimately. | N×M interfaces; most complex; wrong factory → silent device mismatch; contradicts single-type goal. |
| **Proxy** | Structural: provide a substitute or placeholder for another object; controls access before/after delegating. — https://refactoring.guru/design-patterns/proxy | **Helps** for lazy/cached/guarded torch: `CachedYouTubeClass` analog → `LazyModuleProxy` (virtual proxy), `AccessProxy` (requires_grad check), `RemoteProxy` (tensor on worker); `BlockMeta.execute()` lazy-inits heavy `torch.nn.Module` only when edge traversed. **Hurts** if papering over fragmentation — proxy with same `Tensor` interface but different semantics breaks `torch.compile` identity. | Latency; `isinstance` breakage; lazy OOM hidden until exec; cache key expensive; masks incompatible verdict as lazy convertible. |
| **Null Object** *(Introduce Null Object — refactoring, not GoF 22)* | Refactoring: instead of `null`, return a null object that exhibits default behavior (subclass with `isNull()==true`, do-nothing `getPlan()`). — https://refactoring.guru/introduce-null-object | **Helps** to eliminate `if x is None` / `if dtype=="Any"` sprawl: return `NullTensor`/`NullModule` (`forward`=no-op, `isNull()=True`) instead of `None` from `catalog.get(name)`; handles `WILDCARD_TYPES` via polymorphism (Python: `customer = order.customer or NullCustomer()`). **Hurts** where `None` signals truly missing required tensor (e.g. no `torch.Tensor` to `Conv2d`); silent no-op corrupts loss/gradients, invisible in eager graph; fights `mypy`/`torch.jit`/`Optional[Tensor]` idiom. | Silent NaN propagation far from source; extra `Null*` class per family; debuggability loss; violates torch `Optional` convention. |
| **Template Method** | Behavioral: define the skeleton of an algorithm in the superclass but let subclasses override specific steps without changing its structure. — https://refactoring.guru/design-patterns/template-method | **Helps** to unify duplicated `open→extract→analyze→compose` → `validate→coerce_params→build_layer→infer_dtypes→execute` in `BlockMeta`/`core/pipeline.py`; pull `GameAI.turn()` skeleton (`collectResources→buildStructures→buildUnits→attack`) into base `BlockTemplate`, subclasses override `coerce()`, `build()`. **Hurts** if variants need different skeletons — `final` skeleton locks extension; inheritance static vs runtime dtype dispatch needs new subclass per skeleton vs `Strategy` runtime swap. | LSP violation if subclass suppresses step; more steps → harder to maintain; static class-level, not runtime. |

## TL;DR for Grilling

- **Best bets to reduce types:** **Facade** (one canonical Tensor API) + **Strategy** (pluggable conversions) + **Template Method** (unify block lifecycle). **Adapter** as temporary migration bridge.
- **Use sparingly:** **Decorator** (dtype/device layering), **Proxy** (lazy/caching), **Bridge** (only if two orthogonal dimensions truly explode).
- **Usually hurts unification:** **Composite**, **Factory/Abstract Factory** (codify families), **Null Object** (hides `None` that should error).
